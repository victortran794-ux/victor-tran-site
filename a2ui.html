Agent-to-User Interface

A static prototype for turning agent intent into trusted, inspectable user interfaces. The page uses A2UI-style thinking, but does not claim a production Google A2UI implementation.

Mode
Direct-link prototype
Sample
Portfolio refresh assistant
System
Brief, JSON, rendered UI, DNA
Status
Review draft
Problem

Chat is thin when an agent needs to show scope, evidence, risk, progress, approval, and recovery.

Idea

The agent sends structured intent. The site renders that intent through trusted portfolio-native components.

Guardrail

This demo is static, public-safe, and based on a fictional portfolio review workflow.

Prototype frame

One request, four interface layers

The same agent response is shown as a human brief, structured JSON, a rendered UI, and inspection notes. The point is not the bot. The point is the control surface around the bot.

01

Brief

Human request

Review the public homepage and propose one safe improvement. Stay inside the existing design system, cite what you inspected, explain risk, and ask before changing anything.
  • Public homepage only
  • No protected case-study edits
  • No sitemap or nav changes
  • Approval required before file edits
02

A2UI-style JSON

Structured intent

{
  "task": "portfolio_refresh_review",
  "scope": ["index.html", "css/style.css"],
  "guardrails": [
    "public pages only",
    "preserve nav and sitemap",
    "ask before edits"
  ],
  "components": [
    { "type": "status", "state": "ready_for_review" },
    { "type": "evidence", "source": "homepage featured grid" },
    { "type": "recommendation", "risk": "low" },
    { "type": "approval", "actions": ["approve", "revise", "park"] }
  ]
}
03

Rendered UI

Trusted component output

Status Ready for review
Evidence Homepage Work grid and Visual archive section inspected.
Risk Low. Copy-only change. No layout or visibility changes.
04

DNA notes

Why the UI exists

Scope guard
Shows what the agent is allowed to touch before any work starts.
Evidence card
Turns claims into inspectable sources instead of vague confidence.
Approval panel
Keeps the human in control when the next step changes files.

Trusted component catalog

States an agent UI should make visible

These are small, reusable surfaces. They make an agent feel less like a magic text box and more like a clear work system.

Status card

Names the current state: planning, reviewing, waiting, editing, blocked, or complete.

Source card

Shows where the agent looked and what evidence supports the recommendation.

Scope guard

Separates allowed work from protected areas before the agent acts.

Recommendation

Presents a proposed change with reason, expected effect, and review notes.

Approval panel

Turns the next step into a clear human decision: approve, revise, park, or stop.

Recovery state

Explains rollback, undo, and what happens if a tool fails or the result is wrong.

Positioning note

This is interface design for agentic work.

The page is meant to show how Victor thinks about human control, not to present a live automation product. It can stay direct-link only until the prototype earns a public place on the site.
